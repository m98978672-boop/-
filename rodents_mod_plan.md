# План мода: колонии мышей и крыс

## Цель

Мод для **Minecraft Java 1.20.1** на **Fabric** (Java 17, Fabric Loader + Fabric API).
Главная идея — не просто добавить мобов, а сделать несколько устойчивых колоний, которые добывают пищу, размножаются, расселяются, **сами строят свои норы из собранных материалов**, **воюют друг с другом** и постепенно меняют окружающий мир — но **не расходуют его**.

Это **мод-симулятор вредителя**: у игрока нет специальных механик вроде приручения, торговли или крафта. Всё взаимодействие с игроком ограничено *последствиями* (испорченные грядки, подкопы, украденная из сундуков еда, драки под окнами) и *наблюдаемостью* (звуки, следы, холмики у норы). Никаких новых предметов и инструментов колоний в плане не добавляется.

> Числа и опасные события вынесены в настройки. Все значения ниже — дефолт, а не догма.

### Зафиксированные решения

| Вопрос | Решение |
| --- | --- |
| Версия / загрузчик | Minecraft 1.20.1, Fabric, Java 17 |
| Норы | Вход копается, камеры и тоннели **строятся грызунами из добытых материалов**. NBT-шаблон — только чертёж (план), а не источник блоков |
| Главный принцип стройки | **Блок не может появиться «из воздуха»**: сколько колония добыла и принесла — столько и поставила |
| Главный принцип мира | **Мир меняется, но не исчезает:** нулевой баланс блоков, журнал изменений и откат (раздел 8) |
| Главный принцип войны | **Война расходует население, а не мир:** только выбор уже вырытых тоннелей, никакого разрушения ландшафта |
| Игровой цикл игрока | Отсутствует — чистый симулятор-вредитель |
| Появление колонии | Редкий естественный спавн по условиям (структуры при генерации мира не добавляются) + колонии-беглецы после войны |
| Графика | Модели и текстуры делает автор мода в ванильном стиле; звуки — ванильные, позже заменяются |
| Настройки | JSON-конфиг сервера (без клиентских зависимостей) |

## 1. Виды: мышь и крыса

| | Мышь | Крыса |
| --- | --- | --- |
| Здоровье | 6 (3 сердца) | 10 (5 сердец) |
| Размер (хитбокс) | 0,4 × 0,5 блока | 0,6 × 0,7 блока |
| Скорость | высокая, много скачков | ниже, но упорнее |
| Что таскает | семена, зёрна, мелкие плоды | любую пищу, включая морковь/картофель/хлеб |
| Носит стройматериал | маленький комок (1 блок) | 1 блок, иногда 2 ходки подряд |
| Строит | холмик, тоннели, подстилку | камеры, вход, аварийные пробки |
| В бою | кусает и отскакивает, берёт числом, легко паникует | держит строй, бьёт в группе, идёт на помощь сородичам |
| Отношение к другому виду | **жертва** крыс | **охотник** на мышей |
| Дроп при смерти | 0–1 семена (съеденная добыча) + несомый блок | 0–1 шкурка + несомый блок |

Оба вида — `AnimalEntity`, заводить их вручную нельзя: размножение только внутри колонии при достатке еды.

## 2. Колония

- Колония появляется с группой из **3–4 особей** одного вида.
- Данные колонии: `colonyId`, вид, `homePos` (главная камера), список входов и дополнительных нор, запас еды, **запас стройматериалов по типам**, текущий чертёж стройки, **состояние отношений с соседями**, память об угрозах, счётчик особей, флаг тревоги, время основания.
- **Мыши и крысы в одной колонии не смешиваются.** Новая колония другого вида может занять соседние чанки, но не ту же нору.
- Максимум — **60 особей** на колонию.
- В одном чанке — не больше **10 мышей и крыс суммарно**.
- **Глобальные лимиты на измерение**: не более **800 грызунов** и **24 колоний**. При достижении лимита новые колонии не появляются, рост существующих приостанавливается.
- При переполнении чанка грызуны **не исчезают**: 1–2 особи физически уходят пешком в соседний подходящий чанк (не телепортируются), роют там вход, **строят камеру из общего запаса материалов** и остаются частью колонии — так появляется филиал.
- Если места или еды нет — размножение приостанавливается. Лимиты **никогда не вызывают принудительного удаления** уже существующих мобов.
- **Выгруженные чанки:** колония в них полностью замирает — ни роста, ни голода, ни стройки, ни расселения, ни войны. Мод не загружает чанки принудительно и не симулирует колонии «в фоне». Запасы и популяция восстанавливаются из сохранённых данных при загрузке чанка.
- **Смерть колонии:** если погиб последний член, нора помечается заброшенной. Постройки остаются как есть, данные вычищаются через 3 игровых дня, нору может занять новая колония (в том числе другого вида).

## 3. Появление первых колоний (естественный спавн)

Спавн отдельный, не ванильный, уважает `doMobSpawning` и `mobGriefing`.

**Условия для точки спавна:**
- ночь или тёмное помещение, уровень освещения ≤ 7, небо перекрыто (амбар, подвал, нора у стены);
- твёрдая земля под ногами, свободное место над головой;
- **пища поблизости** в радиусе 12 блоков: зрелые культуры, компостер, стог сена, грядка, куст ягод;
- расстояние до ближайшей колонии — не меньше **4 чанков**;
- лимиты колоний и грызунов не достигнуты.

**Как ищется место:** раз в **400 тиков (20 с)** игра берёт один случайный чанк из уже загруженных, рядом с которым есть игрок, и делает 8 попыток найти точку по условиям выше. Если нашлась — спавнится группа 3–4 особей и создаётся колония.

**Предпочтение местности (по приоритету):** деревни и их поля → фермы и амбары игроков → дикие поляны у воды с ягодами и травой → подвалы и пещеры до Y = 50.

**Второй путь:** расселение из существующих колоний (раздел 2) — идёт гораздо чаще естественного спавна.
**Третий путь:** группа беглецов после войны (раздел 7.4) — колония, потерявшая нору, но выжившая, может осесть на новом месте.

## 4. Пища

- Грызуны ищут пищу сами: **зрелые культуры** (`CropBlock#getAge() == getMaxAge()`), упавшие предметы, кусты ягод, стога сена, компостеры.
- Списки блоков и предметов задаются **тегами** (`#minecraft:crops` + конвенция `#c:crops` Fabric), чтобы работали культуры из других модов. Хардкода конкретных культур нет.
- Опознанная пища **относится в нору пешком** — телепорта предметов нет. Несомая пища видна (при смерти падает на землю).
- В хранилище пища считается в **единицах пищи**: семена и зёрна — 0,5, овощи и плоды — 1, хлеб и мясо — 2. Хранится в `SavedData`.
- **Сено — двойного назначения:** это и еда (2 единицы), и подстилка для камеры. Голодная колония съедает запас подстилки, и стройка встаёт.
- **Кража с грядок и из сундуков** разрешена только при включённом `mobGriefing`. Сундуки: берётся 1 предмет из стека, приоритет — еде.
- **Грядка не разоряется:** берётся не больше 30% зрелых растений с одной грядки, последнее зрелое растение не трогается, `farmland` и сам блок культуры не ломаются (снимается только урожай).
- **Часть семян теряется при переноске** и остаётся в земле — из этих потерь потом поднимается новое растение (событие «рост/семена»). Поле восстанавливается само.
- Пища **портится**: −1% запаса за игровой час (настраивается, можно выключить).

## 5. Размножение и взросление

- Размножение идёт автоматически, без участия игрока, при выполнении **всех** условий:
  - в хранилище ≥ **8 единиц пищи** (порог настраивается);
  - в колонии есть свободное место (< 60);
  - в чанке норы < 10 грызунов;
  - глобальные лимиты не достигнуты;
  - прошёл cooldown пары — **1 игровой день (20 мин)**.
- При спаривании тратится 8 единиц пищи, рождается **1–3 детёныша** (обычно 2).
- Детёныш взрослеет за **1 игровой день (20 мин)**, масштаб модели — 50% от взрослого.
- При нехватке пищи или превышении лимитов новые детёныши не появляются; **голодная колония** теряет 1 особь за 2 игровых дня, если запас еды равен нулю и добыча не приносит результата (мягкий регулятор, настраивается).
- Детёныши не добывают пищу, не строят и **не воюют**, но едят из запаса — заметный минус к скорости накопления на старте.
- **Размножение конкурирует со стройкой и войной за еду:** при запасе ниже 8 все силы идут на добычу, а воюющая колония тратит запас быстрее обычного (бойцы едят усиленно).
- **Регуляторы численности** работают вместе: еда, территория, коты и — на верхнем уровне — **войны** (раздел 7.4). Поэтому колонии упираются в локальный предел раньше глобального.

## 6. Норы, стройка и территория

### Главный принцип

**Ни одного блока из воздуха.** Сколько блоков колония добыла, принесла и сложила — столько она может поставить. NBT-шаблон камеры используется **как чертёж**: он задаёт форму и порядок ячеек, но материалы берутся из запаса колонии. Нет запаса — стройка останавливается, и никакая магия её не заменяет.

Учёт строгий: `поставлено ≤ добыто − потеряно`. Каждый блок, поставленный колонией, в отладке логируется вместе с материалом и причиной (чертёж / пробка / холмик / война).

### 6.1. Что добывают и где это берут

| Материал | Источник | Роль |
| --- | --- | --- |
| земля, дёрн, песок, гравий, глина, снег, мох | копают мягкие породы (по тегам) | основной стройматериал, засыпка, аварийные пробки, холмик |
| щепа и палки | грызут поваленную и сухую древесину, валежник | каркас входа, крепление тоннеля |
| сено | тащат стога сена из деревень и с ферм | подстилка в камере, видимая кладовая (и еда при голоде) |
| листья, трава, папоротник | собирают с земли в лесу | мягкая подстилка, маскировка входа |

Добыча идёт **по одному блоку**: грызун выгрызает/подбирает блок, берёт его «в зубы» (видно на модели) и несёт к норе. Дальность ходки ограничена **24 блоками** от входа норы.

### 6.2. Приоритеты работ (строго по порядку)

1. **Еда.** Голодная колония (запас < 8) не строит вообще.
2. **Авария:** пробка в туннеле, куда идёт вода или лава.
3. **Вход и холмик:** защита и маскировка уже прорытого входа.
4. **Камера:** ячейка за ячейкой по чертежу.
5. **Отнорок / дополнительный вход.**
6. **Уют:** подстилка, «кладовая» из сена (визуальное обогащение норы).

**Война вклинивается в этот список:** при активном конфликте работы 3–6 приостанавливаются, силы уходят на защиту входа и бойцов (раздел 7).

### 6.3. Правила постановки блоков (защита мира)

Ставить можно **только**:
- в ячейку текущего чертежа;
- в позицию аварийной пробки;
- в холмик над входом;
- в устье чужого входа при запечатывании во время войны (раздел 7.3).

Запрещено всегда:
- поверх жидкостей (кроме аварийной пробки, поставленной точно в направлении течи);
- поверх блоков с block entity (сундуки, бочки, печи, верстаки, кровати);
- поверх блоков, поставленных игроком;
- **поверх блоков ванильных структур** — деревня, амбар, шахта, крепость остаются нетронутыми (проверка `StructureAccessor#getStructureAt`);
- поверх других грызунов, мобов и игрока;
- поверх блока из чёрного списка в конфиге;
- где угодно при выключенном `mobGriefing`.

Заменять можно только мягкие породы и листву, и только «сначала выгрызть»: снятый блок уходит в запас материалов, а не исчезает.

**Защита построек игрока:** базово — эвристика по тегам (доски, камень, кирпич, стекло, бетон в «мягкие» теги не входят). Опционально — миксин на `BlockItem#place`, запоминающий «блок поставлен игроком»; надёжнее, но по умолчанию выключен.

### 6.4. Вход и холмик

- Вход — наклонный подкоп до **12 блоков** вглубь.
- Над входом насыпается **холмик из земли** высотой 1–2 блока с лазом: заметный признак норы.
- Копать можно только мягкие породы по тегам; **абсолютный запрет:** жидкости и всё вплотную к ним, bedrock, обсидиан, reinforced deepslate, руды, блоки с block entity, блоки ванильных структур, чёрный список.

### 6.5. Камеры

- Чертёж: `3×3×3` (малая) и `5×3×3` (большая), глубина от входа — **до 15 блоков**.
- 1 камера на каждые 10 особей, максимум **6**.
- Внутри — подстилка из сена/листьев; в нише — видимая «кладовая» (сено), фактические запасы живут в `SavedData`.
- Порядок постройки: сначала стены и потолок по чертежу, потом подстилка, входы закрываются последними.

### 6.6. Аварии и вода

- При обнаружении течи сначала ставится **пробка** (глина, песок, земля) точно в направлении воды, затем ремонтируется тоннель.
- Строить и копать в воде нельзя — сначала перекрыть, потом работать.
- Приоритет аварии выше любой стройки: затопленная камера — это потеря запасов и детёнышей.

### 6.7. Темп работ

- Рабочая особь ставит **1 блок за 40–80 тиков**; столько же времени уходит на добычу и перенос.
- Ориентир: бригада из 4 особей с готовым запасом строит первую камеру за **1 игровой день (20 мин)**.
- Реальный темп задаёт **добыча**, а не укладка. Это осознанный выбор — иначе мир застраивается слишком быстро.
- Стройка — ночная активность. Днём грызуны спят в норе, работы замирают (это же и разгрузка сервера).

### 6.8. Дом и территория

- Грызуны помнят `homePos` своей колонии, возвращаются к нему и не путают с чужими норами.
- Возле норы тревога распространяется на членов колонии: `alert` с координатой и типом угрозы, радиус 16 блоков.
- Колония защищает дом: при вторжении крысы атакуют, мыши разбегаются по отноркам.
- **Память об угрозах:** до 16 записей (позиция, тип, время) со сроком 2 игровых дня. Живёт в данных колонии, а не в NBT отдельной особи.
- **Хищники** (коты, оцелоты, лисы) — естественный регулятор популяции и главный источник этих записей. Отдельного хищника мод не добавляет.

## 7. Войны колоний

Колонии конкурируют за территорию и еду, и конкуренция может перерасти в открытый конфликт. Война — высшая точка симуляции, и она подчиняется главному принципу: **расходуется население, а не мир**. Победитель не разрушает чужую нору, а **занимает её**.

### 7.1. Кто с кем воюет

- **Крысы против мышей** — видовая вражда. Крысы сильнее поодиночке и охотятся на мышей даже вне войны; мыши берут числом, скоростью и умением разбегаться по отноркам. В наступление обычно идут крысы.
- **Колонии одного вида** — территориальная конкуренция: два мышиных или два крысиных поселения делят еду и место.
- **Союзов между видами не бывает** никогда: мышь и крыса вместе не воюют. Внутри одного вида возможны и перемирие (раздел 7.5), и **коалиция против общего врага** (раздел 7.9).
- Никто не воюет с игроком: цель конфликта — всегда другая колония.

### 7.2. Причины и эскалация

Напряжённость растёт, если выполнено хотя бы одно:
- норы ближе **16 блоков** или зоны добычи пересекаются;
- обе колонии тянут еду с одних и тех же грядок и сундуков;
- игрок убил 5+ особей одной колонии — сосед чувствует слабость и становится агрессивнее (оппортунизм);
- одна колония упёрлась в лимит чанка (некуда расти), а рядом чужая нора.

Лестница эскалации, каждая ступень — игровые дни:

| Ступень | Что происходит | Длительность |
| --- | --- | --- |
| **Нейтралитет** | колонии не знают друг о друге или игнорируют | — |
| **Напряжение** | разведчики ходят к чужой норе, метят территорию, растёт счётчик враждебности | 1–2 игровых дня |
| **Набеги** | отряды 2–4 особей воруют еду из чужой норы и с чужих грядок | 1–3 игровых дня |
| **Война** | открытые стычки, осада норы, попытки запечатать вход | 3–10 игровых дней |
| **Захват** | победитель занимает чужую нору и запасы; проигравший уходит или погибает | 1 игровой день |
| **Перемирие** | обязательный откат: обе стороны зализывают раны | 2–5 игровых дней |

Счётчик враждебности падает, если колонии не соприкасаются (одна выгружена, разошлись по расстоянию) или если одна потеряла больше половины состава.

### 7.3. Как воюют физически

**Отряд.** На набег или бой колония выделяет **2–6 особей** (не больше 30% состава и не больше 6 одновременно). Отряд собирается у входа норы, идёт вместе по кратчайшему маршруту, у него есть командир — самая здоровая крыса. Возможны и одиночные стычки на границе, без отряда.

**Что делают:**
- **Драка.** Крысы бьют и держат строй, мыши кусают и отскакивают. Урон ванильный, но с ограничением: за одно столкновение каждая сторона теряет **не больше 2 особей**.
- **Ограбление.** Главная цель отряда — **чужие запасы еды** в норе и на грядках. Забирают, уносят к себе, едят. Захваченная еда пересчитывается в единицах пищи и не «исчезает».
- **Запечатывание входа.** Отряд забрасывает чужой вход землёй по правилам аварийной пробки (раздел 6.6): блоки только из принесённого с собой материала, только в устье, по одному. Колония-жертва потом разгребает вход сама.
- **Осада.** Пока вход запечатан, у жертвы кончаются запасы — голод бьёт сильнее любой драки.
- **Захват.** Победитель занимает **уже вырытую** врагом камеру: пространство переиспользуется, а не роется заново. Туннели переходят победителю целиком как дополнительная нора-филиал, запас еды — по правилам раздела 8.

**Чего на войне нет:** яда, огня, взрывов, разрушения блоков, атак на постройки игрока и на самого игрока (кроме уже описанной самозащиты прижатой крысы).

### 7.4. Последствия

- **Потери.** Побеждённая колония теряет 30–70% состава, победившая — 10–30%. Это естественный регулятор численности поверх котов.
- **Беглецы.** Колония, потерявшая больше половины состава и нору, не исчезает: уцелевшие становятся одиночками без колонии. **Группа из 3+ беглецов одного вида может основать новую колонию** на новом месте, если рядом есть еда и место (те же условия, что при естественном спавне, раздел 3). Если места нет — они гибнут от голода и котов обычным путём, без принудительного удаления.
- **Пустые норы.** Оставленная нора помечается заброшенной и позже заселяется — прежней колонией, победителем или новой.
- **Трофеи.** Погибшие не исчезают бесследно: остаётся то, что они несли. Добыча победителя растёт, поэтому война иногда **усиливает** одну колонию вместо того, чтобы ослабить обе.
- **Равновесие.** Численность падает до уровня еды и территории, и колонии упираются в свой локальный предел, а не в глобальный лимит мода. Возникает цикл: рост → теснота → война → беглецы → новые колонии → новая теснота.

### 7.5. Мир и перемирие

- **Мирные условия** (любое останавливает войну): враждебность упала до нуля; у обеих колоний запас еды < 4; обе потеряли треть состава; норы разошлись на 16+ блоков.
- **Перемирие обязательно:** после войны 2–5 игровых дней ни новая война, ни набеги невозможны. Кулдаун на войну для пары колоний — **5 игровых дней**.
- **Предел: не больше 3 активных конфликтов** (фазы «война» и «захват») на измерение и не больше **2 войн на одну колонию** одновременно.

### 7.6. Война и игрок

- Война очень заметна: писк, топот, драки, отряды, бегущие гуськом, запечатанные входы, тела. Для игрока это лучшее зрелище мода и естественный способ понять, что колонии живут своей жизнью.
- Игрок влияет **косвенно**: убитые особи ослабляют колонию и делают её целью соседей; снесённая нора ломает логистику; выпущенные коты меняют баланс.
- Никаких новых предметов, гаджетов и интерфейса войны не требуется — как и было решено.

### 7.7. Производительность войн

- Отряды тикают чаще обычных колоний (**раз в 20 тиков**), но одновременно в мире — не больше **12 бойцов** на измерение.
- Конфликт тикает **раз в 40 тиков**, offset по ID пары; активные конфликты лежат в отдельной таблице `WarState` в `SavedData`, а не перебираются попарно каждый тик.
- Пары колоний хранят **одну симметричную запись** на пару, не две.
- Дальность поиска противника — **64 блока** между норами: дальше колонии друг о друге не знают и воевать не могут.
- Война **не грузит чанки**: если одна сторона выгружена, конфликт замирает целиком.

### 7.8. Настройки

| Ключ | Дефолт | Смысл |
| --- | --- | --- |

| `warMaxActiveConflicts` | 3 | одновременных войн на измерение |
| `warMaxFighters` | 6 | размер отряда |
| `warCooldownDays` | 5 | кулдаун на войну для пары колоний |

### 7.9. Коалиции

Одиночная колония может не справиться с сильным соседом — тогда две колонии **одного вида** заключают союз против общего врага. Это верхний слой войны: он включается только тогда, когда обычной конкуренции уже недостаточно.

- **Кто может.** Только колонии одного вида (мыши с мышами, крысы с крысами) и **ровно вдвоём**: союз из трёх и более превращается в снежный ком и не допускается.
- **Против кого.** Только против противника, который заметно сильнее (на 30%+ по численности) или уже воюет с одной из союзниц. Союз против колонии, с которой есть перемирие, невозможен.
- **Что получают.** Совместные отряды до **8 бойцов** (не больше 4 с каждой стороны), общая цель и координация: одна колония давит на вход, вторая грабит запасы и грядки.
- **Чего нет.** Общих нор, общих запасов, обмена едой и совместной стройки — каждый живёт сам за себя. Бюджет изменений мира не увеличивается: союз не даёт права менять больше блоков.
- **Пределы.** Не больше **одной коалиции** на измерение одновременно; норы союзников не ближе 24 блоков друг к другу (иначе они сами конкуренты и союз не заключается).
- **Сохранность мира.** Коалиция подчиняется тем же правилам, что и обычная война: захватывается только уже вырытое, входы запечатываются принесённым материалом, ни один блок не разрушается.
- **Распад.** Союз распадается через 1–2 игровых дня после исчезновения общей угрозы (враг разбит или заключён мир), а также при провале операции или потере трети состава. После распада — кулдаун **5 игровых дней**, чтобы бывшие союзники не пересобирались бесконечно. Никакой вражды «за предательство» не возникает: бывшие союзники возвращаются в нейтралитет.
- **Данные.** `CoalitionState` в `SavedData`: одна запись на союз (две колонии, общий враг, таймеры, кулдаун).
- **Производительность.** Союз тикает раз в 40 тиков, как конфликт; общий лимит бойцов на измерение (12) сохраняется, поэтому коалиция не увеличивает число одновременно активных мобов.

## 8. Принцип: мир меняется, но не исчезает

Это требование ко моду целиком, а не к одной механике. Мод **изменяет** мир — оставляет норы, тропы, холмики, подстилку, — но **не расходует** его: ни один блок не пропадает бесследно, ни один участок не превращается в пустошь, любую правку можно откатить.

### 8.1. Нулевой баланс блоков (zero-sum)

- В коде **нет операции «просто убрать блок»**. Снятый блок либо уходит в запас материалов колонии, либо на его месте сразу ставится другой (облицовка, подстилка, пробка).
- **Война тоже ничего не разрушает:** запечатанный вход — это блоки из запаса нападающих, захваченная нора — уже вырытое пространство. Ни одного нового блока не «тратится на военные нужды» без источника.
- Единственное исключение — природные события (раздел 9), ограниченные по площади, отключённые по умолчанию и полностью записываемые в журнал.
- Проверка: сумма «снято + поставлено + осталось в запасе + захвачено» совпадает до единицы. В отладке сверка идёт раз в игровой день и пишется в лог.

### 8.2. Бюджет изменений

| Уровень | Лимит |
| --- | --- |
| Одна колония | не больше **400 изменённых блоков за игровой день** |
| Один чанк | не больше **100 изменённых колониями блоков** суммарно за всё время |
| Один чанк | выгрызено не больше **15%** мягких пород чанка |
| Измерение | не больше **8 изменений блоков в секунду** суммарно (стройка + события + война) |

При исчерпании бюджета колония **перестаёт менять мир** до следующего игрового дня: добыча и стройка останавливаются, жизнь идёт дальше. Это ключевая гарантия — даже большая колония не может быстро «съесть» участок. Военные запечатывания входят в тот же бюджет.

### 8.3. Ничто не уничтожается целиком

- **Дерево остаётся деревом.** Стволы берутся только у поваленных, сухих и валежных; стоящее дерево не валится, листва не срубается, пень остаётся.
- **Поле остаётся полем.** С грядки берётся не больше 30% зрелых растений, последнее зрелое не трогается, `farmland` не ломается. Потерянные при переноске семена дают всходы — поле восстанавливается само.
- **Деревня остаётся деревней.** Блоки внутри ванильных структур не трогаются вообще (проверка по `StructureAccessor`).
- **Недра неприкосновенны.** Руды, bedrock, обсидиан, reinforced deepslate, жидкости — вне игры.
- **Биом не выкашивается.** 15% мягких пород на чанк означают, что после работы колонии чанк всё ещё выглядит как этот чанк.
- **Нора не яма.** Тоннели обшиваются и остаются закрытыми; открыто только устье под холмиком.
- **Война не оставляет выжженной земли.** После конфликта остаются драки, тела, запечатанные входы и брошенные норы — но ландшафт цел, и участок по-прежнему пригоден для жизни: и для игрока, и для следующей колонии.

### 8.4. Журнал изменений и откат

- Каждая правка мира пишется в **журнал изменений**: позиция, старый блок, новый блок, `colonyId`, тик, причина (чертёж / пробка / холмик / событие / война / голод).
- Журнал — кольцевой буфер в `SavedData` на измерение, по умолчанию **50 000 записей** (настраивается), старые записи старше **30 игровых дней** удаляются.
- **`/rodentcolonies rollback <colonyId> [n]`** — возвращает последние `n` правок колонии: норы засыпаются, участок возвращается к исходному виду. В том числе отменяет **захват чужой норы**, если указан победитель.
- **`/rodentcolonies stop`** — мгновенно запрещает любые изменения мира: мобы живут, бегают, едят из запаса, воюют, но ничего не копают и не ставят. Аварийный тормоз для сервера.
- **`safeMode` в конфиге** — мод считает и логирует будущие правки, но не применяет их. Режим первого запуска на живом мире: смотришь в логе, что колония собиралась сделать, и решаешь, включать ли.
- Опционально: `/rodentcolonies journal` — сводка «сколько блоков изменено, где, какой колонией».

### 8.5. Совместимость с существующими мирами

- Мод **не генерирует структуры**, не создаёт измерения и не вмешивается в генерацию — старый мир не «перегенерируется» и не теряет сгенерированные чанки.
- Все действия — только в уже загруженных чанках (раздел 2), принудительной загрузки нет.
- **Удаление мода из сборки безопасно:** норы, холмики и тропы остаются обычными блоками, ванильные данные не повреждены. Мир после удаления мода полностью валиден.

## 9. Природные события

Одна общая проверка планировщика: **каждые 100 тиков (5 с реального времени)**. Выбирается один случайный уже загруженный чанк, затем взвешенная лотерея события. Вероятность на проверку считается как `p = 1 / (10 × T)`, где `T` — средний интервал в игровых часах (1 игровой час = 1000 тиков = 50 с реального времени).

| Событие | Средний интервал | p за проверку | Реально |
| --- | --- | --- | --- |
| Семена, саженцы, рост растений (в том числе восстановление съеденных грядок) | 1 игровой час | 10% | ≈ раз в 50 с |
| Рыхление почвы и перенос осадка у воды | 3 игровых часа | 3,3% | ≈ раз в 2,5 мин |
| Локальное затопление | 1 игровой день | 0,42% | ≈ раз в 20 мин |
| Выгорание (лесной пожар) | 5 игровых дней | 0,083% | ≈ раз в 1 ч 40 мин |

Ограничения поверх таблицы:
- **Не чаще одного разрушительного события на измерение за игровой день**, независимо от лотереи.
- **События тоже подчиняются принципу раздела 8:** они меняют мир, а не расходуют его.
  - **Выгорание** идёт только по листве, траве, папоротнику, цветам и сухостою. Брёвна и стволы **не сгорают** — дерево после события остаётся деревом. Пожар тушится модом принудительно, расползаться за площадку не может, площадь — **не больше 24 блоков за событие**. Выгоревшая площадка встаёт в очередь на восстановление через событие «рост».
  - **Затопление** временное: вода ставится на 1–2 блока глубины, только в естественном рельефе (никогда внутри построек), и **отводится через 1–2 игровых дня**. Земля меняется, блоки не пропадают; `farmland` портится до земли, но не исчезает.
- Событие срабатывает только в подходящем чанке и по условиям: выгорание — сухие/жаркие биомы, без дождя; затопление — только рядом с водой и с перепадом высот.
- Мод **не загружает чанки ради событий**. Нет подходящего загруженного чанка — проверка пропускается.
- **По умолчанию выгорание и затопление выключены.** Тестировать на отдельном мире или копии.
- Отдельная опция конфига — «события могут затрагивать постройки игрока» (по умолчанию выключено).

## 10. Наблюдаемость (вместо игрового цикла)

Механик для игрока нет, но мод должен быть **заметен**, иначе он работает «в тумане»:

- **Звуки:** шорох, писк, грызение, укладка блока, драка (на старте — ванильные `entity.bat.*`, `entity.rabbit.*`, `entity.silverfish.*`, позже свои ogg).
- **Холмик** взрытой земли у входа норы и тропинка между грядкой и норой.
- **Видимая работа:** грызун несёт в зубах комок земли, сено или палку. Стройку видно, а не только её результат.
- **Война как зрелище:** отряды, бегущие гуськом, драки у нор, запечатанные входы, разбегающиеся беглецы. Самый заметный слой мода.
- **Пропавшая морковь из сундука** — уже сигнал игроку.
- **Днём грызуны спят в норе** и не шастают по миру: атмосферно и снимает половину нагрузки.

## 11. Производительность

- Никакого сканирования мира каждый тик: планировщик событий общий на мир, поиск спавна — раз в 400 тиков, логика колонии — по расписанию со сдвигом.
- **Тик со сдвигом:** колония тикает раз в **40 тиков**, offset = `colonyId % 40`; конфликт и коалиция — раз в 40 тиков, offset по ID пары; боевой отряд — раз в 20 тиков, но их не больше 12 на измерение.
- Кэш «колония → нора → чанк» по `ChunkPos`; полный перебор колоний или пар в тике запрещён.
- **ИИ:** пересчёт пути не чаще раза в 40 тиков и только при движении; ограничение длины пути; дневной сон — `setAiDisabled(true)`, `navigation.stop()`. Никаких отдельных потоков: всё в `ServerTickEvents`, мир трогается только из main-потока.
- **Стройка и изменение блоков:** только `setBlockState` с минимальными флагами (без рассылки обновлений соседям и перерисовки), не больше **8 изменений блоков в секунду на измерение** суммарно.
- **Бюджет-предохранитель:** если среднее время тика сервера за последние 100 тиков > 40 мс, размножение, спавн, стройка и **новые конфликты** приостанавливаются до восстановления; ниже 25 мс — включаются обратно. Уже идущий бой затухает сам, без новых атак.
- **Журнал изменений** пишется пакетно (буфер в памяти → сброс раз в игровой день); при переполнении старые записи вытесняются.
- Чанки не грузятся принудительно; нет мобов вне симуляции.
- Лимиты: 10 на чанк, 60 на колонию, 800 грызунов и 24 колонии на измерение, 12 бойцов и 3 конфликта одновременно.

**Метрика приёмки:** +100 грызунов в зоне симуляции дают не более **0,5 мс** к среднему MSPT; воюющие колонии (до 3 конфликтов) — не более **+0,3 мс**.

## 12. Данные и сохранение

- **Колонии — в `SavedData`** (`ServerWorld.getPersistentStateManager()`), с полем `dataVersion` для миграций при обновлениях мода. В `SavedData`: ID, вид, `homePos`, входы, камеры, запас еды, **запас стройматериалов по типам**, текущий чертёж и прогресс стройки, счётчики бюджета изменений на день, память об угрозах, флаг тревоги.
- **Конфликты — в отдельной таблице `WarState`**: одна **симметричная** запись на пару колоний (`colonyA`, `colonyB`, ступень эскалации, счётчик враждебности, фаза, таймеры мира/кулдауна, счёт потерь).
- **Союзы — в `CoalitionState`**: по одной записи на коалицию (две колонии, общий враг, таймеры и кулдаун).
- **Журнал изменений** — отдельный `SavedData` на измерение, кольцевой буфер (см. 8.4).
- **В NBT особи:** `colonyId` (или флаг «беглец» после разгрома), `homePos`, возраст, несомый предмет/блок, состояние (сон / паника / тревога / несёт груз / боец отряда).
- Уважение правил: `mobGriefing` (копание, кража, стройка), `doMobSpawning` (спавн).
- Конфиг — JSON на сервере, с безопасными дефолтами; разрушительные события выключены по умолчанию.

## 13. Ассеты (в ванильном стиле)

Полная спецификация — **`rodents_mod_assets.md`**: точные размеры боксов и пивотов, UV-атласы 64 × 64 с занятыми регионами, палитры в hex, пофейсовые карты пикселей, 13 состояний анимации с числами, настройки рендера и каталог из 14 звуковых событий. Ниже — только сводка.

| Что | Итог |
| --- | --- |
| Модель | код (`LayerDefinition`), `texWidth/texHeight = 64 × 64`; у мыши 10 частей, у крысы 11 |
| Части | тело, голова, морда, 2 уха, 4 лапы, хвост, носимый груз (`carry`) |

## 14. Этапы и критерии приёмки

**Этап 1. Мобы и колония**
- Регистрация мыши и крысы, спавн-яйца для отладки (не для игры), атрибуты, дроп.
- Естественный спавн по условиям, создание колонии, `SavedData`.
- Лимиты (чанк / колония / измерение), голод, размножение, взросление детёнышей.
- Добыча пищи: зрелые культуры по тегам, переноска в нору, кража из сундуков при `mobGriefing`.

*Приёмка:* колония из 3 особей вырастает до 10–15 за ~5 игровых дней, упирается в лимит чанка и начинает расселяться; за 3 игровых дня ни одного падения MSPT выше порога; выгрузка и загрузка чанков не сбрасывает ID и запасы; с грядки никогда не снимается последнее зрелое растение.

**Этап 2. Норы, стройка и территория**
- Добыча стройматериалов по видам (мягкие породы, валежник, сено, подстилка) и склад материалов колонии.
- Носимый груз на модели, перенос к норе, учёт «поставлено ≤ добыто».
- Копание входа, холмик, чертежи камер, постепенная стройка по приоритетам.
- Аварийные пробки, правила запретов, защита построек игрока и ванильных структур.
- **Журнал изменений, `/rodentcolonies rollback`, `/rodentcolonies stop`, `safeMode`.**
- Тревога, память об угрозах, защита норы, хищники из ванильных мобов.
- Расселение пешком с постройкой филиала из общего запаса материалов.

*Приёмка:* первая камера построена целиком из добытого материала за 1–2 игровых дня; при отсутствии запаса стройка останавливается, а не «дорисовывается»; за 3 игровых дня ни один блок не поставлен поверх сундука, постройки игрока, блока структуры или жидкости; пробка останавливает течь; **сверка нулевого баланса сходится до единицы**; **`rollback` возвращает участок к исходному состоянию** (поэтапное сравнение блоков до и после); ни один чанк не потерял больше 15% мягких пород и больше 100 блоков.

**Этап 3. Природные события**
- Сначала только рост/семена (включая восстановление грядок и выгоревших площадок). Затем рыхление и осадок. Затем затопление и выгорание — **по умолчанию выключены**.

*Приёмка:* число событий за 10 реальных часов укладывается в таблицу раздела 9 с отклонением не больше 20%; при выключенных разрушительных событиях мир не меняется ни на один блок; ни одно событие не срабатывает в незагруженном чанке; после выгорания сохранились все стволы, после затопления вода отведена, участок пригоден для жизни.

**Этап 4. Войны колоний**
- Таблица `WarState`, лестница эскалации, счётчик враждебности, оппортунизм после гибели особей от рук игрока.
- Отряды 2–6 особей, командир, маршрут между норами, стычки с ограничением потерь.
- Ограбление чужих запасов, запечатывание входа, осада, захват норы как филиала.
- Беглецы и основание новых колоний выжившими, заброшенные норы.
- Мирные условия, обязательное перемирие, кулдаун, лимиты конфликтов и бойцов.

*Приёмка:* за 20 игровых дней в тестовом мире проходит полный цикл хотя бы один раз: напряжение → набег → война → захват → перемирие; ни одна война не выходит за пределы 64 блоков между норами; за всё время войн **ни один блок не разрушен** (проверка журнала: причины только «пробка/чертёж/холмик/война-запечатывание», все с материалом-источником); ни один грызун не удалён принудительно — проигравшие либо ушли беглецами, либо погибли от ран и голода; потери каждой стороны за столкновение не больше 2 особей; при 3 одновременных конфликтах MSPT держится в пределах +0,3 мс; после разгрома выжившие 3+ особи основали новую колонию не позже 3 игровых дней.

**Этап 5. Коалиции**
- `CoalitionState` (одна запись на союз), `CoalitionManager`, условия создания: один вид, ровно две колонии, общий враг на 30%+ сильнее, норы не ближе 24 блоков, нет перемирия с целью.
- Совместные отряды до 8 бойцов (по 4 с каждой стороны) с координацией целей.
- Распад: угроза исчезла / провал операции / потеря трети состава. Кулдаун 5 игровых дней.
- Лимит: одна коалиция на измерение. Команды `coalition list` и `coalition end <a> <b>`.

*Приёмка:* коалиция возникает хотя бы раз за 20 игровых дней при подходящей угрозе; совместный отряд не больше 8 бойцов; норы, запасы и стройка остаются раздельными (по журналу у каждой колонии свои изменения, ни одного общего); союзники не атакуют друг друга всё время союза; повторный союз невозможен раньше кулдауна; MSPT не растёт выше +0,3 мс; за время коалиции ни один блок не разрушен.

## 15. Решения зафиксированы

Открытых вопросов не осталось. Итог по каждому пункту:

| Вопрос | Решение |
| --- | --- |
| ID мода и пакет | `rodent_colonies`, `com.zuza.rodentcolonies` |
| Лицензия | MIT |
| Грызть ли постройки игрока (дерево) | запрещено, включается опцией |
| Дальность ходки за материал | 24 блока (конфиг) |
| Коалиции | приняты — раздел 7.9, Этап 5 |
| Гибнут ли мыши в бою с крысами | да, но не больше 2 особей за стычку |
| Размер журнала и хранение | 50 000 записей / 30 игровых дней (конфиг) |
| Болезнь/заражение от крыс | **отклонено** — дебаффов игроку нет |
| Кража из сундуков игроков | оставляем: 1 предмет из стека, приоритет еде, только при `mobGriefing` |

**Отложено на после релиза** (не входит в этапы 1–5): варианты текстур «ветеран» и «облезлый», свои записанные звуки вместо ванильных сэмплов, коалиции из трёх и более колоний, любые дебаффы игроку.
