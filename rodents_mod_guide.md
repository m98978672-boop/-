### 1.2. Мод в одном абзаце

Мыши и крысы живут **колониями**. Колония сама добывает еду, размножается, расселяется по соседним чанкам, **своими лапами добывает стройматериалы и строит норы**, воюет с соседями и постепенно меняет мир — но **никогда его не расходует**. Игроку не даётся никаких специальных предметов и интерфейсов: мод живёт своей жизнью, а игрок наблюдает и терпит последствия.

### 1.3. Шесть принципов, которые нельзя нарушать

Эти правила важнее любой отдельной механики. Если решение противоречит принципу — решение неверное.

1. **Блок не из воздуха.** Сколько колония добыла и принесла — столько и поставила. `поставлено ≤ добыто − потеряно`.
2. **Мир меняется, но не исчезает.** Нулевой баланс блоков: нет операции «просто убрать блок». Снятое идёт в запас или заменяется на месте.
3. **Никого не удаляют принудительно.** Лимиты только замораживают рост, а не деспавнят уже существующих.
4. **Никаких принудительных загрузок чанков.** Выгружен чанк — колония замерла целиком.
5. **Всё тяжёлое — по расписанию со сдвигом.** Никакого полного перебора колоний, пар и чанков каждый тик.
6. **Любую правку мира можно откатить.** Каждое изменение попадает в журнал с причиной и материалом-источником.

### 1.6. Что мод НЕ делает

Полезно держать рядом, чтобы не расползался объём:

- не добавляет предметов, инструментов, блоков и GUI для игрока;
- не генерирует структуры и не вмешивается в генерацию мира;
- не создаёт измерения и биомы;
- не грузит чанки;
- не добавляет хищников (использует ванильных котов, лис, оцелотов);
- не воюет с игроком;
- не разрушает постройки игрока и ванильные структуры (деревни, амбары, шахты).

### 2.3. Получение проекта

**Рекомендуется — генератор шаблона.**

1. Открой `https://fabricmc.net/develop/template/`.
2. Заполни: Mod Name `Rodent Colonies`, Package `com.zuza.rodentcolonies`, Minecraft Version `1.20.1`, остальное по умолчанию.
3. Скачай zip и распакуй **в корень этого репозитория** (файлы `build.gradle`, `gradlew`, `src/` должны оказаться рядом с `rodents_mod_plan.md`).
4. Открой папку в IDEA как Gradle-проект, дождись синхронизации.

**Альтернатива — вручную** (если хочется контролировать каждую строку): склонируй `FabricMC/fabric-example-mod`, переключись на ветку `1.20.1` и подставь версии из §2.2. Тогда `settings.gradle` должен содержать репозиторий Fabric:

```groovy
pluginManagement {
    repositories {
        maven { name = 'Fabric'; url = 'https://maven.fabricmc.net/' }
        mavenCentral()
        gradlePluginPortal()
    }
}
rootProject.name = 'rodent_colonies'
```

> В свежем шаблоне плагин называется `net.fabricmc.fabric-loom-remap` (Loom переименован). В старых туториалах встретишь `fabric-loom` — оба варианта рабочие, главное не смешивать версии.

### 2.4. Настройка шаблона под наш мод

**`gradle.properties`** — привести к такому виду:

```properties
org.gradle.jvmargs=-Xmx2G
org.gradle.parallel=true
org.gradle.configuration-cache=true

# Fabric
minecraft_version=1.20.1
loader_version=0.19.5
loom_version=1.18-SNAPSHOT
yarn_mappings=1.20.1+build.10

# Mod
version=0.1.0
group=com.zuza.rodentcolonies
archives_base_name=rodent_colonies

# Dependencies
fabric_api_version=0.92.12+1.20.1
```

**Маппинги: Yarn, а не Mojang.** Свежий официальный шаблон перешёл на Mojang mappings (`loom.officialMojangMappings()`), но **вся документация этого проекта написана по Yarn**, и большинство туториалов для 1.20.1 тоже. Поэтому в `build.gradle` меняем строку маппингов:

```groovy
mappings "net.fabricmc:yarn:${project.yarn_mappings}:v2"
```

Соответствия ключевых классов, чтобы не путаться:

| Yarn (используем) | Mojang (@MojangMappings) |
| --- | --- |
| `AnimalEntity` | `Animal` |
| `ServerWorld` | `ServerLevel` |
| `CropBlock` | `CropBlock` |
| `PersistentState` / `getPersistentStateManager()` | `SavedData` / `getDataStorage()` |
| `TexturedModelData` | `LayerDefinition` |
| `ModelData` | `MeshDefinition` |
| `ModelPartData` | `PartDefinition` |
| `ModelPartBuilder` | `CubeListBuilder` |
| `ModelTransform.pivot(...)` | `PartPose.offset(...)` |
| `ItemPlacementContext` | `BlockPlaceContext` |
| `BlockSoundGroup` | `SoundType` |

Лицензия **MIT зафиксирована** (часть IX). Положи файл `LICENSE` с текстом MIT в корень репозитория — строка `jar { from("LICENSE") }` в `build.gradle` подхватит его в сборку автоматически.

### 2.5. Первый запуск

```bash
./gradlew runClient        # запустить клиент с модом
./gradlew runServer        # запустить сервер (остановка командой stop в консоли)
./gradlew build            # собрать jar в build/libs/
./gradlew genSources       # сгенерировать исходники Minecraft для чтения
./gradlew cleanloom        # сбросить кэш Loom (при странных ошибках сборки)
./gradlew --stop           # остановить демоны Gradle
```

Что должно получиться на этом шаге: игра запускается, в логе есть строка о загрузке `rodent_colonies`, в списке модов он присутствует. Механик ещё нет — это нормально.

### 2.6. Как тестировать (настроить один раз)

| Что | Как |
| --- | --- |
| Тестовый мир | отдельный, суперплоскость с травой и деревней (`/locate structure village` для проверки защиты структур) |
| Бэкап | копия папки `saves/<мир>` перед тестами стройки и событий |
| Ускорение времени | `/time set night`, чтобы колонии работали, и `/gamerule randomTickSpeed` не трогать (он влияет на события) |
| Проверка правил | `/gamerule mobGriefing true` для стройки, `false` для проверки полного запрета |
| Замер MSPT | `/debug start`, затем `/debug stop`; либо мод Spark (`/spark tps`, `/spark profiler`) |
| Быстрая проверка лимитов | наш `/rodentcolonies info` (появится на Этапе 0) |

Полезные ванильные правила для негативных тестов: `doMobSpawning false` (спавн не должен идти), `mobGriefing false` (мир не должен меняться вообще).

### 3.3. Ключевое архитектурное правило

**Ни одна часть мода не меняет мир напрямую.** Только через `ColonyWorldEditor`. Он один:
- проверяет все запреты (`BuildRules`),
- списывает материал из запаса колонии,
- расходует бюджет изменений,
- пишет запись в журнал,
- уважает `mobGriefing`, `safeMode` и `/rodentcolonies stop`.

Это делает выполнимыми сразу три принципа: нулевой баланс, откат и безопасность режимов. Если появится соблазн «поставить блоки быстренько тут» — это ошибка проектирования, а не оптимизация.

## Часть IV. Порядок работ по этапам

Правило: **этап считается закрытым только после прохождения критериев приёмки.** Не начинать следующий на «сыром» предыдущем: война на неготовых норах превратится в случайные драки.

### Этап 0. Каркас (1–3 дня)

**Цель:** собираемый мод, в котором есть регистрация, конфиг, хранилище и команда, но нет механик.

1. Получить шаблон и настроить по §2.3–2.4.
2. Создать `RodentColonies` (точка входа) и `RodentColoniesClient`.
3. Написать `RodentConfig` со всеми числами §1.5 и загрузкой/сохранением JSON. Пока значения только читаются, никем не используются.
4. Создать пустые `ColonyState` и `JournalState` (PersistentState) с полем `dataVersion`.
5. Создать `ColonyWorldEditor` с заглушкой: метод `placeBlock(...)` умеет логировать намерение и ничего не делает.
6. Реализовать команду `/rodentcolonies info` (выводит лимиты и число колоний) и `/rodentcolonies reload`.
7. Завести `MaterialTags` и три json-тега из §3.2 (пока с минимальным содержимым).
8. Добавить `mixins.json` и пустой конфиг миксинов — чтобы потом не переделывать структуру.

**Проверка:** `./gradlew build` проходит; `runClient` показывает мод в списке; `/rodentcolonies info` отвечает; после выхода из мира и возврата конфиг сохранился без изменений.

**Критерий приёмки:** пустой мод собирается, запускается, читает конфиг и хранит `PersistentState` без ошибок в логе.

### Этап 1. Мобы и колония (1–2 недели)

**Цель:** живёт колония: спавнится, ест, размножается, упирается в лимиты.

1. `MouseEntity`, `RatEntity`, `RodentEntity` — свойства, дроп, звуки, спавн-яйцо (только для отладки).
2. `MouseEntityModel`, `RatEntityModel`, `RodentRenderer`, `RodentCarryFeature` — ассеты по `rodents_mod_assets.md`.
3. Анимации §7 из ассетов + команда `/rodentcolonies debug anim`.
4. `Colony`, `ColonyStorage`, `ColonyManager` — создание, поиск, запас.
5. `ColonySpawner` — условия и планировщик раз в 400 тиков.
6. `ForageGoal`, `HaulGoal`, `ReturnHomeGoal`, `SleepGoal`.
7. Размножение, взросление, голод, порча запаса.
8. Лимиты трёх уровней и предохранитель по MSPT.
9. Локализация: `ru_ru.json`, `en_us.json`, подзаголовки звуков.

**Проверка:**
- спавн руками: `/summon rodent_colonies:mouse ~ ~ ~`;
- наблюдение за колонией: `/rodentcolonies info <id>`;
- ускоренный прогон: 5 игровых дней на сервере с `runServer`-сессией;
- замер: `spark tps` и MSPT при 100+ особях.

**Критерий приёмки:** из 3 особей вырастает 10–15 за ~5 игровых дней, колония упирается в лимит чанка и начинает расселяться; выгрузка и загрузка чанков не сбрасывает ID и запасы; с грядки никогда не снимается последнее зрелое растение; MSPT в норме.

**Типичные ошибки:** забыть `EntityType.Builder.dimensions()` (хитбокс не совпадёт с моделью); не прописать атрибуты (моб спавнится с 1 HP); анимации смотрят не в ту сторону (проверить знак поворота на первом запуске).

### Этап 2. Норы, стройка, журнал (2–4 недели)

**Цель:** колония сама добывает материал, строит камеры и **никогда** не портит мир.

1. `BuildRules` — полный список запретов, включая `StructureAccessor` и блоки с block entity.
2. `ColonyWorldEditor` — реальная реализация: списание материала, бюджет, журнал, `mobGriefing`, `safeMode`.
3. `HarvestMaterialGoal` — добыча земли/песка/глины, древесины валежника, сена, подстилки; носимый груз на модели.
4. `NestBlueprint` + `ConstructionSite` + `BuildPlanner` — чертежи камер, очередь ячеек, приоритеты §6.2.
5. Копание входа и холмик; аварийные пробки при течи.
6. `ChangeJournal`, `JournalState`, `/rodentcolonies rollback <colonyId> [n]`, `/rodentcolonies stop`, `safeMode`.
7. Событие «сверка нулевого баланса» раз в игровой день с выводом в лог.
8. `ThreatMemory`, тревога, защита норы, реакция на котов.
9. Расселение: уход пешком, филиал из общего запаса.

**Проверка:**
- включить `safeMode`, запустить колонию, прочитать лог «что собиралась сделать» — и только потом включать реальные правки;
- скопировать мир, построить камеру, сделать `rollback` и сравнить блоки;
- тест «жадность»: задать бюджет 20 блоков в день и убедиться, что стройка встала, а не пробила лимит;
- тест запретов: сундук, деревня, вода, кровать, печь рядом с норой.

**Критерий приёмки:** камера построена целиком из добытого за 1–2 игровых дня; при отсутствии запаса стройка останавливается; ни один блок не поставлен поверх сундука, постройки игрока, блока структуры или жидкости; пробка останавливает течь; `rollback` возвращает участок к исходному состоянию; ни один чанк не потерял > 15% мягких пород и > 100 блоков.

### Этап 3. Природные события (1–2 недели)

**Цель:** мир живёт сам, но разрушения по умолчанию выключены.

1. Планировщик раз в 100 тиков + взвешенная лотерея с `p = 1/(10×T)`.
2. Событие «семена и рост» (включая восстановление съеденных грядок и выгоревших площадок).
3. Событие «рыхление и осадок» у воды.
4. Затопление (временное, с отводом) — **выключено по умолчанию**.
5. Выгорание (только листва/трава/сухостой, без брёвен) — **выключено по умолчанию**.
6. Ограничение «одно разрушительное событие в игровой день на измерение».

**Проверка:** прогон 10 реальных часов на сервере с записью счётчиков событий; сравнение с таблицей §1.5 (отклонение ≤ 20%); отдельный тест с выключенными разрушительными событиями — мир должен остаться байт-в-байт по блокам.

**Критерий приёмки:** числа совпадают с ожиданием; при выключенных разрушительных событиях мир не меняется ни на один блок; ни одно событие не срабатывает в незагруженном чанке; после выгорания все стволы на месте.

### Этап 4. Войны колоний (2–4 недели)

**Цель:** колонии конкурируют и воюют, не разрушая мир.

1. `WarState` — симметричная запись на пару колоний.
2. `Escalation` и `WarManager` — счётчик враждебности, лестница, лимиты (3 конфликта, 2 войны на колонию).
3. `RaidSquad` — сбор отряда, командир, маршрут, ограничение потерь.
4. Ограбление чужих запасов, запечатывание входа, осада, захват норы как филиала.
5. Беглецы и основание новых колоний; заброшенные норы и очистка данных.
6. Мирные условия, перемирие, кулдаун.
7. Предохранитель MSTP: новые конфликты не начинаются при перегрузке.

**Проверка:** длинный прогон 20 игровых дней на сервере; проверка журнала на отсутствие разрушений; проверка, что проигравшие не удалены принудительно.

**Критерий приёмки:** полный цикл напряжение → набег → война → захват → перемирие проходит хотя бы раз; войны не выходят за 64 блока; за всё время войн ни один блок не разрушен; потери за стычку ≤ 2; при 3 конфликтах MSPT в пределах +0,3 мс; выжившие 3+ особи основали колонию в течение 3 игровых дней.

### Этап 5. Коалиции (1–2 недели)

**Цель:** две колонии одного вида могут объединиться против общего сильного врага — и разойтись, когда угроза исчезла.

1. `CoalitionState` — одна запись на союз (две колонии, общий враг, таймеры, кулдаун).
2. `CoalitionManager` — условия создания: один вид, ровно две колонии, общий враг на 30%+ сильнее, норы не ближе 24 блоков, нет перемирия с целью.
3. Совместные отряды: суммарно ≤ 8 бойцов (по 4 с каждой стороны), общая цель и координация — одна давит на вход, вторая грабит запасы.
4. Распад: угроза исчезла (враг разбит или заключён мир), провал операции, потеря трети состава. Кулдаун 5 игровых дней.
5. Лимит: одна коалиция на измерение одновременно.
6. Команды `/rodentcolonies coalition list` и `/rodentcolonies coalition end <a> <b>`.

**Проверка:** тестовый мир с тремя колониями — двумя слабыми одного вида и одной сильной крысиной; убедиться, что союз возник, отряды координируются, союзники не бьют друг друга, а после разгрома общего врага союз распадается и не собирается заново 5 дней.

**Критерий приёмки:** коалиция возникает хотя бы раз за 20 игровых дней при подходящей угрозе; совместный отряд не превышает 8 бойцов; норы, запасы и стройка остаются раздельными (проверка по журналу: у каждой колонии свои изменения); союзники не атакуют друг друга за время союза; союз не собирается повторно раньше кулдауна; MSPT не растёт выше +0,3 мс.

## Часть V. Инструкции по подсистемам

### 5.1. Чек-лист регистрации новой сущности

Чтобы ничего не забыть (порядок важен — на этом спотыкаются чаще всего):

1. `EntityType<T>` с `dimensions()` из §8 ассетов и категорией `MISC`.
2. Регистрация в `Registry.register(Registries.ENTITY_TYPE, ...)`.
3. Фабрика свойств: `FabricDefaultAttributeRegistry.register(type, builder)` — здоровье, скорость, урон.
4. `SpawnEggItem` — только для отладки, пометить комментарием.
5. `ModelLayerLocation` + `TexturedModelData` в клиентском инициализаторе.
6. `EntityRendererFactory` → `RodentRenderer` (+ `RodentCarryFeature`).
7. Лан-ключи: имя сущности, спавн-яйцо, подзаголовки звуков.
8. `sounds.json` + записи в `RodentSounds` (события и питчи).
9. Если моб новый — запись в теги и в `ColonySpawner` (условия, вес).

### 5.2. Как устроен `ColonyWorldEditor`

Один метод на всё изменение мира. Порядок проверок внутри — важен, от дешёвых к дорогим:

```
placeBlock(world, pos, state, colony, reason)
  1. если safeMode или /stop — записать в лог намерение и выйти
  2. если !mobGriefing — выйти
  3. если исчерпан бюджет изменения (колония / чанк / измерение) — выйти
  4. если BuildRules запрещает позицию — выйти
  5. если в запасе нет нужного материала — выйти
  6. списать материал из запаса колонии
  7. установить блок с минимальными флагами
  8. записать в ChangeJournal (позиция, было, стало, colonyId, тик, причина)
  9. учесть в счётчиках бюджета
```

`removeBlock(...)` выглядит так же, но **обязан** положить снятый блок в запас — иначе нарушается принцип нулевого баланса.

### 5.3. Хранение данных

| Что | Где | Почему так |
| --- | --- | --- |
| Запас еды, материалов, камеры, чертёж | `ColonyState` (`PersistentState`) | переживает выгрузку чанков и смерть особей |
| Связь особи с колонией | NBT особи: `colonyId`, `homePos`, возраст, груз, состояние | при выгрузке восстанавливается вместе с мобом |
| Конфликты | `WarState` — по одной симметричной записи на пару | вдвое меньше данных, нет рассинхрона |
| Союзы | `CoalitionState` — одна запись на коалицию (2 колонии, общий враг, таймеры) | союзов мало, и они короткоживущие |
| Правки мира | `JournalState` — кольцевой буфер | нужен откат и аудит |

`dataVersion` обязателен: при обновлении мода читаем старую версию и мигрируем, иначе миры сломаются.

### 5.4. Планировщик: как не уронить сервер

- Колония тикает раз в 40 тиков с offset = `colonyId % 40` — пиков нет.
- Конфликт тикает раз в 40 тиков, отряд — раз в 20, отрядов ≤ 12 на измерение.
- Спавн-проверка — раз в 400 тиков.
- События — раз в 100 тиков.
- Все изменения мира проходят через суточный/секундный бюджет (§5.2, п. 3).
- Предохранитель: если средний MSPT за 100 тиков > 40 мс, стоп роста/стройки/новых войн; ниже 25 мс — возврат.

### 5.5. Состояния особи и приоритет анимаций

Порядок приоритета (сверху вниз): сон → паника → тревога → атака → еда / грызение / укладка → ходьба → покой. Состояние хранится в NBT, чтобы после выгрузки моб не «зависал» в позе укладки.

### 5.7. Ассеты — краткий порядок

## Часть VI. Тестирование

### 6.1. Негативные тесты (обязательные)

Специально ломать поведение, чтобы убедиться в защите:

| Что проверяем | Как | Ожидание |
| --- | --- | --- |
| `mobGriefing false` | выключить правило, дать колонии жить | мир не меняется ни на блок |
| Вода рядом с норой | вылить ведро над тоннелем | пробка, вода не в камере |
| Сундук у входа | поставить сундук с едой | содержимое уменьшается, сам блок цел |
| Деревня рядом | основать колонию у деревни | блоки деревни не тронуты |
| Выгрузка чанков | уйти на 500+ блоков и вернуться | ID колонии, запасы и нора на месте |
| Лимит чанка | 12 особей в чанке | 11-я и 12-я не спавнятся, идёт расселение |
| Перегрузка | поднять 800 особей | рост встаёт, MSPT не выше порога, никто не удалён |
| `rollback` | 500 правок, затем откат | блоки вернулись к исходным |
| `stop` | команда, затем наблюдение | мобы живут, мир не меняется |
| Коалиция | две слабые колонии одного вида против сильной крысиной | союз возник, союзники не бьют друг друга |
| Распад союза | убрать общую угрозу | союз распадается за 1–2 дня, повтор раньше 5 дней невозможен |
| Мир после удаления мода | убрать jar из `mods`, зайти | мир грузится, норы остались обычными блоками |

### 6.2. Замер производительности

1. `/debug start` → поработать 5 минут → `/debug stop`, посмотреть средний тик.
2. `spark tps` и `spark profiler --timeout 120` при 100, 300, 800 особях.
3. Сравнить: +100 особей ≤ 0,5 мс; 3 активных войны ≤ 0,3 мс.
4. Провал теста — повод искать в первой строке профиля: обычно это навигация (`PathNodeMaker`) или обновления света от блоков.

## Часть VIII. Риски и «что делать если»

| Симптом | Причина | Решение |
| --- | --- | --- |
| `Dependency requires at least JVM runtime version 21` | Gradle запускается на JDK 17, а Loom нужен 21 | поставить JDK 21, указать как Gradle JVM |
| Не находятся классы Minecraft в IDE | не сгенерированы исходники | `./gradlew genSources`, переподключить проект |
| Странные ошибки после обновления Loom | кэш | `./gradlew cleanloom` и `./gradlew --stop` |
| Мобы падают с 1 HP | не зарегистрированы атрибуты | `FabricDefaultAttributeRegistry.register` |
| Хитбокс не совпадает с моделью | разошлись `dimensions()` и геометрия | сверить §8 ассетов |
| MSPT скачет после 300 особей | полный перебор или путь каждый тик | проверить offset тиков и cooldown пересчёта пути |
| Свет «дёргается» у нор | блоки ставятся с полными флагами | использовать минимальные флаги в `setBlockState` |
| Колонии не воюют | выгружены чанки одной из сторон | это by design: война идёт только в загруженных чанках |
| Мир «поплыл» после теста | не был включён `safeMode` / нет бэкапа | тестировать на копии; откат через `rollback` |

## Часть IX. Финальные решения

Открытых вопросов больше нет. Всё, что не перечислено здесь, — значение в конфиге, которое меняется без пересборки мода.

| # | Вопрос | Решение |
| --- | --- | --- |
| 1 | ID мода и группа | `rodent_colonies` / `com.zuza.rodentcolonies` — **зафиксировано** |
| 2 | Лицензия | **MIT** — нужен файл `LICENSE` в корне (текст MIT), `build.gradle` подхватит его автоматически |
| 3 | Вредительство у игрока по умолчанию | **средне**: с грядок ≤ 30% зрелых, последнее зрелое не трогается; из сундука 1 предмет из стека; всё только при `mobGriefing`. Дерево построек игрока — запрещено, включается опцией |
| 4 | Дальность ходки за материал | 24 блока (конфиг) |
| 5 | Журнал изменений | 50 000 записей / 30 игровых дней (конфиг) |
| 6 | Гибнут ли мыши в бою с крысами | да, но ≤ 2 особей за стычку |
| 7 | Коалиции | **принято**, Этап 5: только внутри одного вида, ровно 2 колонии, только против общего врага, одна коалиция на измерение |
| 8 | Болезнь/заражение от крыс | **отклонено** — дебаффов игроку нет |
| 9 | Кража из сундуков игроков | оставляем: 1 предмет из стека, приоритет еде, только при `mobGriefing` |

Пункты 1, 2 и 3 прошиты в сборку: их изменение после первого релиза потребует правок в десятках файлов и ломает совместимость сохранений.

## Часть X. Быстрый старт: что делать, когда будет команда «поехали»

> Сейчас выполнено: только документация. Ниже — порядок, с которого начинается код.

1. Поставить JDK 21 и IDEA Community.
2. Сгенерировать шаблон на `fabricmc.net/develop/template` (1.20.1, `com.zuza.rodentcolonies`) и распаковать в корень репозитория.
3. Заполнить `gradle.properties` по §2.4, переключить маппинги на Yarn.
4. Заменить `fabric.mod.json` по §2.4, переименовать главный класс в `RodentColonies`.
5. `./gradlew build` — убедиться, что собирается.
6. `./gradlew runClient` — убедиться, что мод в списке.
7. Создать `RodentConfig` со всеми числами из §1.5 (просто поля и JSON, без логики).
8. Создать пустые `ColonyState`, `JournalState`, `ColonyWorldEditor` — каркасы без логики.
9. Сделать команду `/rodentcolonies info` — она будет главным инструментом отладки на всё время работы.
10. Закоммитить: «Этап 0: каркас проекта».
11. Открыть `rodents_mod_assets.md` §3 и начать рисовать `mouse_gray.png` — это можно делать параллельно с кодом.
12. Сказать, что этап 0 закрыт: дальше идёт регистрация сущностей и спавн.
